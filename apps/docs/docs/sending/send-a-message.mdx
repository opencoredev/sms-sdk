Send a text, read the result, and handle failures without texting anyone twice. No client yet? Start with the [Quick start](/getting-started/quick-start).

## Send and read the result

```ts
import { sms } from "./sms";

const result = await sms.send({
  to: "+14155550123",
  body: "Your order #123 has shipped.",
  idempotencyKey: "order:123:shipped:v1",
});

console.log(result.id, result.provider, result.providerId, result.delivery);
```

`send()` resolves only when a provider accepts the message. This logs the SDK's ID (`sms_` plus 32 hex characters), the adapter name, the provider's message ID, and usually `queued`.

| Field | What it holds |
| --- | --- |
| `id` | The SDK's ID for this message. Stable across idempotent replays. |
| `provider` | The adapter that accepted it. |
| `providerId` | The provider's message ID: Twilio `SM…` or `MM…`, Telnyx `data.id`, Plivo `message_uuid[0]`, Vonage `message_uuid`, Bandwidth `id`, Sinch batch `id`. Store it to match status webhooks. |
| `handoff` | Always `"accepted"`: the provider has the message, not yet the phone. |
| `delivery` | Status from the send response, usually `"queued"`. Delivery arrives later by [webhook](/receiving/webhooks). |
| `encoding`, `segments` | `"gsm7"` or `"ucs2"`, and the estimated segment count. See [Message length and cost](/sending/length-and-cost). |
| `attemptedProviders`, `attempts` | Every adapter and request that ran. Safe to log. |
| `replayed` | `true` when the result came from the [idempotency store](/sending/idempotency) instead of a new send. |

Save the IDs so status webhooks can find the message later:

```ts
import { db } from "./db";
import { sms } from "./sms";

const result = await sms.send({ to: "+14155550123", body: "Your table is ready." });

await db.messages.create({
  id: result.id,
  provider: result.provider,
  providerId: result.providerId,
  to: "+14155550123",
  status: result.delivery,
});
```

## Handle errors

Every error extends `SmsError` and has a stable `code` and a `retrySafe` flag. `retrySafe: true` means the provider did not take the message, so sending again cannot create a duplicate. It does not promise the retry will work.

```ts
import {
  HandoffUnknownError,
  InvalidRecipientError,
  isSmsError,
  PolicyRejectedError,
  ProviderRejectedError,
} from "@opencoredev/sms-sdk";
import { db } from "./db";
import { sms } from "./sms";

export async function notifyShipped(orderId: string, to: `+${string}`): Promise<void> {
  const idempotencyKey = `order:${orderId}:shipped:v1`;
  try {
    await sms.send({ to, body: `Order ${orderId} has shipped.`, idempotencyKey });
  } catch (error) {
    if (error instanceof HandoffUnknownError) {
      // The provider may have the message. Do not resend automatically.
      await db.messages.markNeedsReview(idempotencyKey, error.reason);
      return;
    }
    if (error instanceof InvalidRecipientError || error instanceof PolicyRejectedError) {
      return; // Fix the data or respect the policy. A retry would fail the same way.
    }
    if (error instanceof ProviderRejectedError && error.category === "compliance") {
      await db.suppressions.add(to); // The recipient opted out with the provider.
      return;
    }
    if (isSmsError(error) && !error.retrySafe) {
      await db.messages.markNeedsReview(idempotencyKey, error.code);
      return;
    }
    throw error; // Retry safe: let your job queue try again later.
  }
}
```

:::warning[Never resend after HandoffUnknownError]
After a timeout, network error, 5xx, or malformed success response, the provider may have created the message, so the SDK stops and throws `HandoffUnknownError`. Check the provider's console or API, or wait for a status webhook, before you send again. With an idempotency store, a later send with the same key throws it again instead of sending.
:::

[Errors](/reference/errors) lists every error class, code, and what to do about it. To block sends yourself, for example to people who opted out, see [Block and log sends](/advanced/policy-and-hooks).

## Choose a sender

`to` must be E.164: a `+`, a country code that does not start with 0, and at most 15 digits, with no spaces. `+14155550123` is valid. `(415) 555-0123` is not. The `` `+${string}` `` type cannot prove a number is valid, so the SDK checks it before any request. Narrow user input with `isE164`:

```ts
import { isE164 } from "@opencoredev/sms-sdk";
import { sms } from "./sms";

const input: string = "+14155550123"; // for example, from a form field

if (!isE164(input)) {
  throw new Error("Enter the number with its country code, such as +14155550123.");
}

await sms.send({ to: input, body: "Thanks for signing up." });
```

`isE164` checks format only, and the SDK does not convert national formats. Use a phone number library for that.

`from` is optional when the adapter has a default sender. It takes one of four shapes:

| You send from | Write | Checked locally |
| --- | --- | --- |
| A long code or toll-free number | `"+15550100001"` | E.164 |
| A short code | `{ shortCode: "12345" }` | 3 to 8 digits |
| An alphanumeric sender ID | `{ senderId: "Acme" }` | 1 to 11 letters, digits, or spaces, with at least one letter |
| A provider sender pool | `{ messagingService: "MG…" }` | Not empty. Twilio also checks `MG` plus 32 hex characters. |

| Sender | Twilio | Telnyx | Plivo | Vonage | Bandwidth | Sinch |
| --- | --- | --- | --- | --- | --- | --- |
| Long code, toll-free | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| Short code | ✅ | ✅ | ✅ | ❌ | ✅ | ✅ |
| Alphanumeric sender ID | ✅ | ✅ needs `messagingProfileId` on `telnyx()` | ✅ | ✅ | ❌ | ✅ |
| `{ messagingService }` | Messaging Service SID | Messaging profile ID | Powerpack UUID | ❌ | ❌ | ❌ |

Set a default on the adapter and override it for one message:

```ts
import { createSmsClient } from "@opencoredev/sms-sdk";
import { twilio } from "@opencoredev/sms-sdk/twilio";

const sms = createSmsClient({
  adapters: [
    twilio({
      accountSid: process.env.TWILIO_ACCOUNT_SID ?? "",
      authToken: process.env.TWILIO_AUTH_TOKEN ?? "",
      from: { messagingService: process.env.TWILIO_MESSAGING_SERVICE_SID ?? "" },
    }),
  ],
});

await sms.send({ to: "+447700900123", from: { senderId: "Acme" }, body: "Your parcel is out for delivery." });
```

A sender the first adapter cannot use throws `UnsupportedFieldError` (`field: "from"`) before any request. With fallback on, later adapters that cannot use it are skipped.

The SDK cannot see whether a number belongs to your account, is registered for 10DLC or toll-free, or whether the country allows alphanumeric sender IDs (the United States and Canada do not). The provider rejects those with `category: "sender"`. See [Registration and consent](/providers/registration-and-consent). A sender belongs to one provider account, so a second provider needs its own.

## MMS, scheduling, validity, and status URLs

Each of these fields works only on some providers. If the adapter cannot send one, the SDK throws `UnsupportedFieldError` before any request instead of dropping it. [Choose a provider](/providers/overview#capabilities) has the full table, and `sms.capabilities()` returns it at runtime.

### Send media

```ts
import { sms } from "./sms";

await sms.send({
  to: "+14155550123",
  body: "Here is your boarding pass.",
  mediaUrls: ["https://example.com/passes/abc123.png"],
});
```

Twilio (up to 10 URLs), Telnyx, and Plivo send MMS. Each URL must be absolute `http` or `https` and reachable by the provider, and the body may be empty. Many countries outside the US and Canada do not support MMS, and the provider rejects it there.

### Schedule a message

```ts
import { sms } from "./sms";

await sms.send({
  to: "+14155550123",
  from: { messagingService: "MG00000000000000000000000000000000" },
  body: "Your appointment starts in one hour.",
  sendAt: new Date("2026-12-01T08:00:00Z"),
});
```

The provider holds the message and sends it at `sendAt`, and `send()` resolves as soon as the provider accepts it. Telnyx and Sinch schedule from any sender they support. Twilio schedules only from a Messaging Service and enforces its own lead-time limits. To cancel a scheduled message, use the provider's API or console.

### Set a validity period

`validityPeriodSec` sets how long the provider keeps trying before the message expires. Ranges: Twilio 1 to 36000, Plivo 5 to 10799, Vonage 20 to 604800, Sinch 1 to 2592000. Telnyx and Bandwidth do not support it. Out of range throws `InvalidMessageError`.

```ts
import { sms } from "./sms";

await sms.send({ to: "+14155550123", body: "Your code is 482913. It expires in 10 minutes.", validityPeriodSec: 600 });
```

### Set a status URL for one message

`webhookUrl` sends this message's status updates somewhere other than the URL on your number or account. Twilio, Telnyx, Plivo, and Sinch support it, Vonage only with JWT auth (`applicationId` and `privateKey`), and Bandwidth not at all.

```ts
import { sms } from "./sms";

await sms.send({ to: "+14155550123", body: "Your order has shipped.", webhookUrl: "https://example.com/webhooks/sms/status" });
```

## Provider options

`providerOptions` passes provider parameters the shared fields do not cover, keyed by adapter name. An entry applies only when that adapter sends.

```ts
import type { TwilioSendOptions } from "@opencoredev/sms-sdk/twilio";
import { sms } from "./sms";

const twilio: TwilioSendOptions = { smartEncoded: true };

await sms.send({ to: "+14155550123", body: "Your order “123” shipped.", providerOptions: { twilio } });
```

When Twilio sends this, it replaces the curly quotes with plain ones (`SmartEncoded`). Other adapters ignore the entry. For a parameter with no typed option yet, put its raw name in `extra`: `{ twilio: { extra: { SomeParam: "value" } } }`. Typed options are checked before any request, `extra` values are not. See the [send() reference](/reference/send#provideroptions) and each provider page.

## Cancel a send

Pass an `AbortSignal` to stop waiting:

```ts
import { SendAbortedError } from "@opencoredev/sms-sdk";
import { sms } from "./sms";

const controller = new AbortController();
setTimeout(() => controller.abort(), 2_000);

try {
  await sms.send({ to: "+14155550123", body: "Reminder" }, { signal: controller.signal });
} catch (error) {
  if (error instanceof SendAbortedError) {
    console.log("Stopped before the provider could have the message. Safe to send later.");
  }
}
```

Aborting before any request, or while waiting to retry a rate limit, throws `SendAbortedError`, which is retry safe. Aborting mid-request throws `HandoffUnknownError` with `reason: "aborted"`, because the provider may already have the message.
