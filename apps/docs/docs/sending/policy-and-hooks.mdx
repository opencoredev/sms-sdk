You want to stop messages to people who opted out, and you want logs and metrics for every send without leaking phone numbers or message text. `beforeSend` handles the first. `hooks` handles the second.

## Block sends with beforeSend

`beforeSend` runs once per logical send, after local validation and the idempotency check and before any provider request. Return `{ kind: "allow" }` or `{ kind: "reject", reason }`.

```ts
import { createSmsClient } from "@opencoredev/sms-sdk";
import { twilio } from "@opencoredev/sms-sdk/twilio";
import { db } from "./db";

export const sms = createSmsClient({
  adapters: [
    twilio({
      accountSid: process.env.TWILIO_ACCOUNT_SID ?? "",
      authToken: process.env.TWILIO_AUTH_TOKEN ?? "",
      from: "+15550100001",
    }),
  ],
  beforeSend: async ({ message }) => {
    if (await db.suppressions.has(message.to)) {
      return { kind: "reject", reason: "Recipient opted out." };
    }
    return { kind: "allow" };
  },
});
```

A rejection throws `PolicyRejectedError`. Your `reason` is on `error.reason`, and only there: it stays out of the error message, `toJSON()`, hooks, and the idempotency store, because it may name a person. Nothing is sent, and fallback never runs.

The callback receives `{ id, message, encoding, segments }`: the logical send ID, the `SmsSendInput` as you passed it, and the segment estimate.

- If `beforeSend` throws, that error propagates out of `send()` unchanged and nothing is sent.
- With an idempotency store, a policy rejection is stored as `rejected`, so the same key can be sent again once the policy allows it.
- Keep it fast. It runs inside every `send()`.

Use it for your suppression list, quiet hours, per-recipient rate limits, or a segment budget. SMS SDK does not keep a suppression list for you. [STOP, HELP, and opt-outs](/receiving/stop-help-and-opt-outs) shows how to fill one from webhooks.

## Observe sends with hooks

```ts
import { createSmsClient } from "@opencoredev/sms-sdk";
import { telnyx } from "@opencoredev/sms-sdk/telnyx";

export const sms = createSmsClient({
  adapters: [telnyx({ apiKey: process.env.TELNYX_API_KEY ?? "", from: "+15550100001" })],
  hooks: {
    onAttempt: ({ id, to, attempt }) => {
      console.log("sms.attempt", { id, to, provider: attempt.provider, outcome: attempt.outcome, ms: attempt.durationMs });
    },
    onAccepted: ({ id, provider, providerId, segments }) => {
      console.log("sms.accepted", { id, provider, providerId, segments });
    },
    onFailure: ({ id, errorCode, retrySafe, attempts }) => {
      console.error("sms.failed", { id, errorCode, retrySafe, attempts: attempts.length });
    },
  },
});
```

You see one `sms.attempt` line per provider request, then one `sms.accepted` or `sms.failed` line per send.

| Hook | When | Payload beyond the shared fields |
| --- | --- | --- |
| `onAttempt` | After every provider request | `attempt`: a `SendAttempt` |
| `onAccepted` | Once, when a send is accepted | `provider`, `providerId`, `attempts` |
| `onFailure` | Once, when a send ends in an error | `errorCode`, `retrySafe`, `attempts` |

Every payload has `id`, `to` (masked, such as `+1********23`), `encoding`, `segments`, and `idempotencyKey` when set. Hooks never receive the message body, credentials, or full phone numbers.

A hook that throws or returns a rejected promise is ignored, so a broken logger cannot change a send's outcome. Hooks are not awaited before `send()` returns.

`onFailure` does not run for errors thrown before the send starts: local validation errors, idempotency replays and conflicts, and errors thrown by `beforeSend` itself.

## Logging errors

`SmsError.toJSON()` returns a redacted object (`name`, `code`, `message`, `retrySafe`, `attempts`, `provider`). Provider messages have phone numbers masked and are cut to 200 characters. `cause` is never serialized. Log `error.toJSON()` rather than the raw error when your logger serializes everything.
