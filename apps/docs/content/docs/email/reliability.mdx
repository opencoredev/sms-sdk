---
title: Reliability
description: Configure retries and fallback without risking duplicate delivery.
---

Email delivery can fail before dispatch or after the provider may have accepted a message. The SDK records this difference as `delivery`.

```ts
const email = createEmailClient({
  adapters: [primary, backup],
  retry: { maxAttempts: 2 },
  fallback: { adapters: ["backup"] },
});
```

Fallback continues after `not_sent`. It stops after `unknown` by default because another send may duplicate the email.

## Flush serverless telemetry

`flush` waits for in-flight telemetry and never rejects.

```ts
await email.flush();
```

Disable telemetry with `EMAIL_SDK_TELEMETRY=0` or `telemetry: false`.
