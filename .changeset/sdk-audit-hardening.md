Add `sms.getMessage()`, `parseSmsWebhooks()`, `fromByAdapter`, and suppression-list helpers, and reject invalid configuration and malformed input with typed errors.

- `sms.getMessage(providerId, { adapter?, signal? })` looks a message up with the provider and returns its delivery status, or `undefined` when the provider has no such message. Failures throw `MessageLookupError` (`retrySafe: false`). Implemented for all six adapters through the new optional `SmsAdapter.getMessage`; a Vonage adapter with JWT auth needs `reportsCredentials`. `capabilities()` reports `messageLookup`.
- `parseSmsWebhooks()` returns every event in a request: each element of a Bandwidth callback and each Sinch `recipient_delivery_report` entry. `parseSmsWebhook()` now throws `WebhookPayloadError` for a multi-event payload; it used to return the first Sinch report and drop the rest. Bandwidth status events now include the recipient in `dedupeKey` (`bandwidth:{messageId}:{to}:{type}`) so per-recipient status callbacks do not collide.
- `fromByAdapter` on `send()` input sets a sender per adapter for fallback chains.
- `SuppressionList`, `memorySuppressionList()`, `suppressionPolicy()`, and `applySuppressionEvent()` connect STOP/START webhooks to `beforeSend`.
- Keyword events carry `mediaUrls`.
- `createSmsClient` throws `ConfigurationError` for `idempotency.ttlSec` or `staleReservationSec` that are not positive integers of at least 1 second (`ttlSec: 0` let a repeated key send twice), `timeoutMs` above `2147483647`, malformed `idempotency`/`retry` objects or stores, `retry.maxAttempts` outside 1 to 10, and retry delays outside 0 to `2147483647`. `send()` throws `ConfigurationError` if `idempotency.store.reserve()` throws or returns a malformed record/result, and `memory()` / `memory().enqueue()` throw `ConfigurationError` for malformed options, capabilities, or outcomes.
- `validate()` returns issues instead of throwing for malformed runtime input, and `send()` throws `InvalidMessageError` for it.
- `createSmsClient`, all adapter factories (`twilio`, `telnyx`, `plivo`, `vonage`, `bandwidth`, `sinch`), `send()`, `getMessage()`, and the webhook parsers and verify helpers now fail closed with `ConfigurationError` for missing or malformed options, malformed adapters (including `capabilities.senderTypes`, `capabilities.validityPeriod`, and `providerOptions` specs), invalid `fallback`/`hooks`/`beforeSend`, invalid or non-http(s) `baseUrl` (including credentials, query, fragment, or Unicode whitespace/control characters) or `publicUrl` (including credentials, bare `?`, fragment, or Unicode whitespace/control characters; non-empty query strings remain supported), invalid Vonage `region`, non-function `fetch` or `now`, spoofed or non-`AbortSignal` `signal`, dot-segment `providerId` (`"."` or `".."`), missing/malformed/locked webhook `request`, unsupported webhook `provider`, empty Basic/HMAC/verify-helper secrets, invalid or non-http(s) URLs in Twilio/Plivo verify/compute helpers, unknown Sinch webhook `credentials.kind`, non-Latin-1 Basic credentials, and invalid `toleranceSec` (`NaN`, non-finite, negative, or non-number). `MessageLookupError#toJSON()`, `WebhookSignatureError#toJSON()`, and `WebhookPayloadError#toJSON()` now include `providerName` and `reason` when present. `SinchWebhookVerification` is exported from `@opencoredev/sms-sdk/webhooks`. Sinch `Rejected` delivery status now maps to `undelivered` unless the provider error code is `40003` (`filtered`), and each Sinch `recipient_delivery_report` event takes `occurredAt` from that report's `at`.
- Plivo `rejected` status maps to `undelivered` in webhooks and `getMessage()`, and placeholder `ErrorCode`/`error_code` `000` is omitted.
- `beforeSend` fails closed with `PolicyRejectedError` on malformed or unrecognized decisions without stranding idempotency reservations, and throwing inside `beforeSend` emits `onFailure`. An unexpected internal failure keeps the attempts made.
- `unsafeSkipVerification` throws `ConfigurationError` when `NODE_ENV` is `production`.
- Provider responses and inbound webhook request bodies are read up to 1 MiB; an oversized provider response is an unknown outcome, an oversized webhook body throws `WebhookPayloadError` (`reason: "body_too_large"`) before signature verification, and an aborted or unreadable webhook body stream throws `WebhookPayloadError` (`reason: "body_unreadable"`).
- Every subpath export adds a `default` condition beside `import`. The package stays ESM only.
- `send()`, `validate()`, `createSmsClient()`, adapter factories, and webhook parsers snapshot caller-supplied inputs and options upfront (preserving class-instance `hooks`, `fromByAdapter`, and factory/sender getters), deep-freeze exported capability constants and `capabilities()`/`defaultFrom` copies, validate `Date` and `RegExp` brand slots, require plain objects for `providerOptions` entries and `extra`, trim only HTTP OWS around `trustProxy` headers, and treat non-string `verifyTelnyxSignature`/`verifySinchSignature` inputs as invalid signatures.
